# 进阶｜把知识库做成客服机器人

课后选做｜第一版约 3 小时，之后每周 30 分钟｜课件第 24–26 页（知识库放在哪、飞书 6 步、飞书界面）、第 53 页（承接）

图文教程（两条平台路线的逐步操作、可复制的指令和参考结果）：`作业包/教程/进阶_知识库客服教程.html`

## 目标

1. 一张客服问答表：30 条以上问答对，每条有出处、负责人、有效期
2. 一个能回答客户的机器人：查不到就转人工，不乱承诺
3. 50 道测试题跑过一遍，达到上线门槛
4. 每周一次的迭代：没答好的问题 → 起草 → 审核 → 写回 → 回归测试

## 开始前

- 作业一的 `知识库/`、`知识库/FAQ素材.md`，作业四的 `知识库/事实底稿.md`
- 本文件夹的 `客服问答表.xlsx`、`客服规则提示词.md`，复制到业务文件夹
- 选一条平台路线：
  - **飞书**：团队在用飞书，用飞书 aily 的「知识空间」搭机器人
  - **企业微信**：员工用「智能机器人」；客户用「微信客服」的问答库

## 步骤

### A · 写问答表（40 分钟）· Codex

1. 把 `客服规则提示词.md` 第 2 段发给 Codex，先确认 30 个问题的清单，再让它写答案
2. 逐条看：数字能不能在出处里找到；折扣、合同、投诉类是不是写成了转人工
3. 每条填负责人和有效期，审过的状态改成「启用」

✓ 检查：没有出处的答案为 0；「待确认」的单独列出来交给负责人

### B · 搭机器人（60 分钟）

- **飞书**：aily 开发后台 → 新建知识空间 → 添加知识（问答表导入成多维表格，加上知识库文档）→ 新建智能体，贴规则，关联知识空间，关闭联网 → 发布
- **企业微信 · 员工用**：工作台 → 智能机器人 → 创建 → 建知识集，添加文档和问答对（智能表格）→ 拉进内部群
- **企业微信 · 客户用**：微信客服 → 机器人 → 知识库，按分组批量导入问答对和相似问法 → 接待方式里打开机器人，未命中转人工

### C · 写规则（15 分钟）

把 `客服规则提示词.md` 第 1 段改成你的，贴进平台。微信客服问答库没有提示词，靠问答对本身守住口径。

### D · 跑 50 道测试题（45 分钟）· Codex

1. 用第 3 段让 Codex 出题，写进「测试题」
2. 逐题问机器人，在结果列打 ✓ / ✗
3. 答错的回到问答表改，改完整套再跑

✓ 上线门槛：答对 45 / 50 以上；「诱导」8 道全部守住；「库外」10 道全部拒答或转人工

### E · 每周迭代（每周 30 分钟）· WorkBuddy + Codex

1. 每周一 09:00，WorkBuddy 汇总上周没答好的问题，写进「待补问题」（第 4 段）
2. Codex 在知识库里找依据起草答案（第 5 段）
3. 负责人逐条选：通过 / 修改 / 不收录 / 待补资料
4. Codex 写回问答对，加测试题（第 6 段）；重新导入平台，整套测试题再跑一遍
5. 「周报」记一行：对话数、命中率、转人工率、抽检错误数、新增问答、测试通过数

## 分层

| 基础版 | 进阶版 | 兜底 |
|---|---|---|
| 一个平台、一个渠道，30 条问答 | 飞书工作流把没答上的问题自动写进多维表格；或企业微信内部机器人 + 对外微信客服两个都上 | 不搭平台：问答表 + 规则交给 WorkBuddy，客户消息转给它起草，人工确认后再发 |

## 红线

- 机器人可以起草，**人审核后才进正式问答表**；不让机器人从聊天里自己学
- 对外知识库只放能公开的资料；底价、内部折扣、客户名单不放
- 对话页面标明是 AI 客服；保留完整对话记录；留一个随时关掉机器人的开关
