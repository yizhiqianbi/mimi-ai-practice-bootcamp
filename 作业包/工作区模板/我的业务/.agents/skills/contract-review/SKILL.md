# 合同初审（Codex）

## 一句话调用

> 用 contract-review 审一下 资料/____合同.docx

## 输入

- 对方的合同：`资料/` 里的 docx 或 pdf
- 我方底线：`知识库/` 里的合同模板、付款说明、售后条款；或者一张 `底线.md`（付款节点、交期起算、质保年限、违约金上限、验收方式、发票）
- 这单的情况：金额、交期、客户是谁（来自报价或询价）

## 步骤

1. **抽条款**：把合同拆成条款清单：编号、标题、原文要点
2. **对照底线**：每条对照我方底线，标三种颜色：
   - 红：超出底线，必须改（例：违约金按日 1%、验收不合格无限期退货）
   - 黄：要谈（例：付款节点和我们不同、交期从签约日起算）
   - 绿：和我们一致
3. **写改法**：每条红和黄都写：原文、问题在哪、建议改成的条款原文（可以直接粘进合同）、依据（我方哪份文件哪一条）
4. **漏项**：我方模板里有、对方合同里没有的条款（例：不可抗力、知识产权、送货范围），列出来
5. **回复草稿**：一封给对方的邮件，语气客气，只提红色和最重要的黄色，附修改条款
6. 在对话里只回：几红几黄、最要命的一条是什么

## 规则

- 这是初审，不是法律意见。金额超过 ____ 万、涉及担保、独家、诉讼管辖的，建议交给律师
- 不编法条和条款号；引用法律只写法律名称
- 只起草，不发送
- 合同原件不上传到任何外部网站

## 输出

- `产出/日期_合同审查_客户名.md`：红黄绿表、修改条款、漏项、回复草稿
- `产出/日期_合同审查_客户名.xlsx`：同样的表，方便法务或老板批注

## 验收

- [ ] 合同里每一条都出现在表里，没有漏
- [ ] 每条红黄都有可以直接粘贴的改法和依据
- [ ] 回复邮件没有被发出
